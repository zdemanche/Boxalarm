# Architecture Spine: Boxalarm — Architecture

## Service Inventory & Boundaries
1. `alerting-service` — dispatch ingress, per-member channel fan-out/escalation, department-level tone ladder (tones 1-3), mutual-aid prompt, receipts, self-test, canary, alert audit log — isolated life-safety plane, own DynamoDB table, own SNS FIFO topic, own SQS FIFO queues + DLQs.
2. `platform-service` — Cognito triggers, department config (`ALERT_RULES` etc.), Verified Permissions policy admin, cross-service audit-log sink, data export — shared DynamoDB table.
3. `personnel-service` — roster, quals, attendance, LOSAP points, availability, duty shifts, open-shift signup — shared DynamoDB table.
4. `apparatus-service` — apparatus registry, check sheets, defects, OOS tracking, maintenance, SCBA, testing schedules, compartments — shared DynamoDB table.
5. `incident-service` — NERIS-native incident model, pre-population, guided completion, NERIS submission, submission status, search — own dedicated DynamoDB table.
6. `training-service` — certifications, expiry alerting, drills, training hours, transcripts — shared DynamoDB table.
7. `reporting-service` — chief dashboard, LOSAP/ISO/grant reports, response-time analytics, CSV/PDF export — no primary store, reads GSIs on the shared `platform-service` table (OpenSearch deferred).
8. `inspections-service` — occupancy, pre-incident plans, inspection/violation tracking, hydrants, map retrieval — shared DynamoDB table.
9. `inventory-service` — equipment/PPE registry, consumable stock, asset lifecycle — shared DynamoDB table.
10. `notification-service` — non-alert member/officer notification (cert expiry, defect routing, testing-due, PPE expiry, reorder, shift-coverage gaps); LOB failure domain, shares no queue/concurrency/provider account with alerting — shared DynamoDB table.
11. `web-spa` — React web SPA, single app, serves officer/chief/training/apparatus/admin desk workflows — `apps/web` in `boxalarm-ui`.
12. `mobile-app` — React Native app (iOS + Android, one codebase), the alerting path-of-record surface with native Critical Alerts / full-screen-intent modules — `apps/mobile` in `boxalarm-ui`.
13. `infrastructure` — all Pulumi IaC for every AWS resource/environment across all services — sole owner of AWS deploys, `boxalarm-infrastructure` repo.

Physical DynamoDB layout is **3 tables**, not 10: `alerting-service` and `incident-service` each own a dedicated table; the other 8 services (platform, personnel, apparatus, training, reporting, inspections, inventory, notification) share the `platform-service` table. Service code boundaries remain 10 regardless.

## Tech Stack Decisions
- Language: TypeScript/Node.js LTS across all 10 backend services (no Python — no AI/ML workload).
- Compute: AWS Lambda, arm64, zip for simple handlers / Alpine Docker image for anything container-shaped — pay-per-invocation for a hard volunteer-municipal budget constraint.
- Ingress: API Gateway HTTP API (not REST API) + custom Lambda authorizer — JWT validation, rate limiting, routing decisions stay in app code (house ruling against managed API-gateway products; requirements §8 pins API Gateway/Lambda, reconciled as TLS/routing-only ingress).
- Data: DynamoDB on-demand, 3 tables total (see Service Inventory). No Aurora — no ad-hoc join/report requirement exists. Streams on for all 3 tables from day one (future OSI/CQRS trigger, unused in v1).
- Search/reporting: v1 = purpose-built DynamoDB GSIs. OpenSearch (OSI pipeline) explicitly deferred on cost-floor grounds; fast-follow trigger = second department live, or incident/narrative-search volume exceeding a GSI+FilterExpression's interactive range.
- Messaging: **two transports, deliberately different.** Alerting = SNS FIFO topic `boxalarm-{env}-alerting-topic.fifo` → per-channel SQS FIFO queues + DLQs (FIFO ordering + `MessageDeduplicationId` load-bearing for exactly-once; EventBridge has no FIFO mode). LOB/domain = EventBridge bus `boxalarm-{env}-platform-bus`, rule-routed to per-consumer SQS + DLQ (no ordering requirement). One-way bridge only: an allow-listed set of alerting events republish outward to the LOB bus; nothing on the LOB bus can reach into alerting.
- Orchestration: Step Functions or EventBridge Scheduler one-time timers for escalation/tone-ladder timing and NERIS retry/backoff — no in-Lambda sleep loops.
- Cache: ElastiCache Serverless Valkey — config/reference data and reporting aggregations only, explicitly a soft dependency, never the alerting hot path, never gates readiness.
- IaC: Pulumi, `boxalarm-infrastructure` repo exclusively owns all AWS resources; `boxalarm-backend`/`boxalarm-ui` are build-only.
- Identity: Amazon Cognito, single user pool per environment.
- Authorization: AWS Verified Permissions, Cedar policies; `IsAuthorizedWithToken` / `BatchIsAuthorizedWithToken` (list endpoints never a per-item authz loop); fail-secure 503 on a Verified Permissions outage everywhere except `alerting-service`'s core fan-out/escalation background pipeline (no per-request authz decision on that hot path).
- No self-hosted broker (no Kafka/RabbitMQ) — AWS-native only, pay-per-use, no 24/7-staffed-support-compatible.
- Frontend: no MFE shell/remote split (single team, single release train, hard budget constraint). One React web SPA (`react-router-dom`, TanStack Query) + one React Native app (New Architecture, bare RN not Expo managed, React Navigation). Shared internal packages `@boxalarm/core`, `@boxalarm/design-tokens`, `@boxalarm/i18n` in a `boxalarm-ui` npm workspace (Yarn/npm workspaces, not Nx/Turborepo).
- Native notification layer is hand-written Swift (iOS Notification Service/Content Extension) and Kotlin (`FirebaseMessagingService` + foreground service) — the only hand-written native code; everything else is shared TS/RN.

## Naming Conventions
- Resource naming is `boxalarm-{env}-*` everywhere; any `moonaan-prod-*` name appearing anywhere in the document is template boilerplate superseded by this rule.
- Repos: exactly 4, all under personal GitHub `zdemanche` — `boxalarm-ui` (RN app + web SPA + shared packages, build-only), `boxalarm-backend` (all Lambda service code, build-only), `boxalarm-infrastructure` (all Pulumi, sole AWS owner), `boxalarm-docs` (architecture/PRD/backlog, no code). Never a monorepo, never per-service repos.
- Endpoints: base path `/api/v1/{service}/...`, JSON camelCase, RFC 7807 errors carrying `traceId`, contract-first OpenAPI per service.
- Events: lowercase dotted `{domain}.{entity}.{past-tense-verb}` — canonical form; any PascalCase shorthand elsewhere in the source document (`DispatchReceived`, `ResponseConfirmed`, `MemberUpdated`, `CertExpiring`, `CheckCompleted`, `IncidentSubmitted`) must be read as, and implemented as, the dotted form. PascalCase names must never appear in code, config, or EventBridge rule patterns.
- DynamoDB keys: `ENTITY_TYPE#value` convention on `pk`/`sk`/`gsiNpk`/`gsiNsk`; `{deptId}` present in every table PK from day one (F9.6 tenancy seam) even with one department in operation.
- S3 object prefixes: `{deptId}/{entityType}/{entityId}/{filename}`.

## Cross-Cutting Non-Negotiables
- **Auth: no MFA, no step-up, no session expiry, ever.** `MfaConfiguration: OFF`, no enrollment flow, no role-conditional MFA. Access/ID tokens: 1 hour. Refresh tokens: 3650 days (Cognito ceiling), identical on native and web, silently renewed (`automaticSilentRenew` web, foreground+401 refresh on `react-native-app-auth`), rotation enabled with a grace window. No idle timeout, no periodic forced re-authentication anywhere. Export (`POST /platform/export`) and destructive admin actions are gated by a Cedar chief/admin role check **alone** — no re-authentication challenge. Revocation (Cognito global sign-out on `personnel.member.updated` status change, per-device admin revocation) is the only control that ends access, not expiry. Fail-secure: a Verified Permissions outage returns 503, never a defaulted allow, except on `alerting-service`'s hot-path fan-out/escalation logic which has no per-request authz check at all.
- **Event envelope** (every event, every domain): `eventId` (UUID, dedup key), `eventTime` (ISO-8601), `eventType` (`{domain}.{entity}.{verb}`), `source`, `correlationId` (the `dispatchId` for alerting), `schemaVersion` (semver), `payload` (domain-specific object).
- **Error envelope**: RFC 7807 (`type`, `title`, `status`, `detail`) plus `traceId` (W3C `traceparent`/`tracestate` propagated on every inter-service call).
- **Exactly-once alerting key — 4 segments, amended.** DynamoDB conditional put on `idempotencyKey = {dispatchId}#{toneSequence}#{memberId}#{channel}`, guarded by `attribute_not_exists(idempotencyKey)`. `DELIVERY_RECEIPT.sk = RECEIPT#{memberId}#{channel}#{toneSequence}` — this exact segment order (a different order breaks range queries). The 3-segment forms `dispatchId#memberId` and `dispatchId#memberId#channel` (no tone) are both **explicitly wrong** and must never appear in code — both are silent-suppression defects on record from prior review rounds. `MessageDeduplicationId = hash(dispatchId, toneSequence, memberId, channel)` is a transport-layer optimization only, never the enforced guarantee; `MessageGroupId` stays `dispatchId` (spans every tone). `BatchWriteItem` cannot carry a `ConditionExpression` — never use it for any conditional alerting write; use `TransactWriteItems` or per-item `PutItem`.
- **`toneSequence` is a literal, immutable field of each EventBridge Scheduler payload**, assigned once at schedule-creation time (`{dispatchId, toneSequence: 2}` for T+180s, `{dispatchId, toneSequence: 3}` for T+360s) — never computed from observed ladder state at fire time. EventBridge Scheduler is at-least-once; computing "current + 1" at fire time lets a redelivered invocation mint the next tone early, which is itself a duplicate-storm generator.
- **`channelTier` is escalation-state bookkeeping ONLY — never a routing filter, never a dedup input.** Routing and dedup both key on `channel` (`push`|`sms`|`voice`) alongside `toneSequence`. This is stated five times in the source document on purpose: push and SMS share the tier `primary`; a tier-keyed dedup or routing decision makes their two publishes collide and SNS FIFO silently discards one — no error, no DLQ, no receipt, and the N1.2 parallel-channel guarantee is gone. Regression tests are mandatory: (1) one dispatch, one member, assert two distinct provider sends at T+0 (push+SMS); (2) one member answers `NOT_RESPONDING` at tone 1, tone 2 fires — assert a *new* delivery record on the same channel, not swallowed by the tone-1 key.
- **New amendment entities** (all in the `alerting-service` table): `DISPATCH_RESPONSE_RECORD` (append-only per-answer audit, `sk = RESPONSE#{memberId}#{answeredAt}`), `ALERT_RULES_COPY` (denormalized tone-ladder/predicate config, `pk = DEPT#{deptId}#ALERT_RULES`), `TONE_EVENT` (two shapes: singleton fire-guard `sk = TONE#{toneSequence}`, and append-only audit row `sk = TONE#{toneSequence}#{evaluatedAt}`), `MUTUAL_AID_EVENT` (singleton, `sk = MUTUALAID#SINGLETON`), and the officer mutual-aid-prompt item namespace `sk = MAPROMPT#{memberId}#PUSH` — deliberately disjoint from `RECEIPT#...` so an already-toned officer's receipt key can never collide with their mutual-aid prompt.
- **Notification identity on both push platforms is `{dispatchId}#{toneSequence}`**, never `dispatchId` alone: iOS `apns-collapse-id` and the Android notification id passed to `NotificationManager.notify()`. A `dispatchId`-only identity lets the OS silently coalesce a tone-2 push into tone-1's existing notification — no second buzz, no re-fire, receipt still says "delivered." Every tone must get its own presentation even if tone 1 is still on screen or already answered.
- **Alerting-plane IAM isolation** (N1.5/N1.7, enforced not just documented): `alerting-service` execution roles hold **no IAM permission** to read or write the `platform-service` or `incident-service` tables. Fan-out reads `MEMBER_ELIGIBILITY_SNAPSHOT`, `PRE_PLAN_COPY`, and `ALERT_RULES_COPY` — all denormalized copies living in the alerting table itself, event-propagated from the owning services, never a synchronous cross-service call. The one sanctioned exception in the reverse direction: `POST /platform/export`'s dedicated read-only role, which may read all three tables, Cedar chief/admin-gated, alarmed on every invocation.
- **Deployment topology**: AWS serverless (Lambda arm64 + API Gateway HTTP API + DynamoDB + SNS/SQS/EventBridge + Step Functions/EventBridge Scheduler), single-tenant with a `{deptId}`-scoped multi-tenant seam, U.S.-region-pinned (NERIS + N6.1), Pulumi-deployed via GitHub OIDC → central org role from `boxalarm-infrastructure` alone, per-environment isolation (dev/qa/staging/prod) with distinct NERIS credentials/base URL/User-Agent per environment (N6.4 — dev traffic must never reach NERIS prod).
- **Retention/no-TTL for life-safety and compliance evidence.** `DELIVERY_RECEIPT`, `ESCALATION_EVENT`, `DISPATCH_ALERT`, `DISPATCH_RESPONSE_RECORD`, `TONE_EVENT`, `MUTUAL_AID_EVENT`, `NERIS_SUBMISSION_ATTEMPT`, `INCIDENT`/`INCIDENT_SECONDARY`, `AUDIT_LOG_ENTRY` — no TTL-based deletion, ever; retention governed by a scheduled export-to-S3-Glacier job (default 7 years, N6.3-configurable), not item expiry.
- **Fire-only, no PHI/EMS/ePCR** — the largest scope boundary; keeps HIPAA/BAA/NEMSIS entirely out.
- **N1.7 is documented as NOT literally satisfied** at the topic/table/region/fan-out-Lambda layer — these are accepted single points of failure with no alternate path. Retained parallel tone-out radio paging (N1.9) is the compensating control and is therefore **not optional** until the SPOF table changes. Chaos testing is scoped to the channel layer only, never asserted to cover topic/table/region survival.
