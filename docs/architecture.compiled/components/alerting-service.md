# Alerting Service

## Purpose & Boundaries
Life-safety plane: dispatch ingress (port + adapters), fan-out, per-member channel escalation, department tone ladder (F1.12–F1.14), mutual-aid prompt (officer manual-prompt adapter only), delivery receipts, self-test (F1.10), canary (N1.6 = same pipeline, `isTest: true`), alert audit (F1.11), live roster (F1.7). Handlers (not separate units): Live Roster, Canary Monitor, Tone Evaluator. Own DynamoDB table (Streams on, PITR on, customer-managed KMS), own SNS FIFO topic, per-channel SQS FIFO queues (push/sms/voice) + DLQs, own reserved concurrency. Never reads platform/incident tables. Ingress adapters write the same `DISPATCH_ALERT`: SES inbound email (SPF+DKIM+allowlisted From, DMARC; token is noise-cutter not auth) and signed JSON webhook on its OWN REST API (per-source path `<CAD_WEBHOOK_URL>/<deptId>.<sourceId>`, `x-api-key` = capacity partition 5 rps/burst 5, HMAC-SHA256(secret, timestamp+"."+rawBody), ±300 s, replay cache TTL 900 s, two active keys). Manual-entry adapter = N1.8 degraded mode. Fail-closed auth, fail-open parsing (template miss pages raw, address `SEE DISPATCH TEXT`, VERIFY). Dept from authenticated source config, never message body. Incident number = dispatch identity (24h; no number -> text fingerprint 10 min); later message = UPDATE (`DISPATCH_UPDATE`, non-escalating push-only to roster, `CADUPDATE#{updateId}#{memberId}#PUSH` claims), never a second page.

## Interfaces
Base `/api/v1/alerting`: POST `/ingress/{adapter}` (Vendor; CAD webhook actually elsewhere); POST/GET `/dispatches` (manual create Cognito(admin); list = fail-open); GET `/dispatches/{id}` (+`toneLadder{status,currentToneSequence,nextToneAt,predicateGaps}`); GET `/home-locality`; GET `/dispatches/{id}/roster`; POST `/dispatches/{id}/responses` (ETA optional, epoch seconds; 409 `SUPERSEDED`; `clientAnswerId`/`Idempotency-Key`, `Idempotent-Replayed: true`, 409 `ANSWER_ID_REUSED`, replay guards 7d; latest answer by `answeredAtMs`); GET `/dispatches/{id}/receipts` (admin); POST `/self-test`, GET `/self-test/{testId}`; POST `/receipts/push|sms|voice` (Vendor; must round-trip `toneSequence`); GET `/audit`, `/canary/status`, `/delivery-baseline`, `/dispatches/{id}/diagnostics[/{memberId}]` (admin, FAIL-CLOSED); POST `/devices/state`; POST `/dispatches/{id}/tone-ladder/advance|halt`, `/mutual-aid/trigger|acknowledge` (admin); health pair. Riding-board routes live under apparatus-service paths but are alerting-plane. 17 `ALERTING_PLANE_ROUTES` fail open (see infrastructure).

## Data Ownership
Alerting table (`pk=DEPT#{deptId}#DISPATCH#{dispatchId}` unless noted): `DISPATCH_ALERT` (sk METADATA; toneLadderStatus ACTIVE|HALTED_MANUAL|COMPLETED, currentToneSequence, nextToneAt, gsi2pk `DEPT#{deptId}`/gsi2sk `DISPATCH#{dispatchedAt}`); `DELIVERY_RECEIPT` (sk `RECEIPT#{memberId}#{channel}#{toneSequence}`, immutable, `idempotencyKey`, `deviceSends` six states SENT|VALIDATED|INVALID|REFUSED|UNAVAILABLE|FAILED, `deviceAttempts`, gsi1 `MEMBER#{memberId}`/`RECEIPT#{sentAt}#{dispatchId}`, no ttl); `DISPATCH_ROSTER_ENTRY` (sk `ROSTER#{memberId}`; ackStatus NONE|RESPONDING|NOT_RESPONDING|DIRECT_TO_SCENE, lastAnsweredTone; conditional update `attribute_not_exists(ackAt) OR :newAckAt > ackAt`); `DISPATCH_RESPONSE_RECORD` (sk `RESPONSE#{memberId}#{answeredAt}`, append-only); `ESCALATION_EVENT` (sk `ESCALATION#{memberId}#{toneSequence}#{escalatedAt}`); `TONE_EVENT` (singleton guard `TONE#{toneSequence}` + audit `TONE#{toneSequence}#{evaluatedAt}`; outcome FIRED|FIRED_MANUAL_OVERRIDE|SKIPPED_PREDICATE_MET|SKIPPED_ALREADY_FIRED|SKIPPED_MANUALLY_HALTED|SKIPPED_NO_CONFIG); `MUTUAL_AID_EVENT` (sk `MUTUALAID#SINGLETON`, conditional put); officer prompt item `MAPROMPT#{memberId}#PUSH` (idempotencyKey `{dispatchId}#MUTUALAID#{memberId}#push`); `DISPATCH_UPDATE`. Other partitions: `MEMBER_ELIGIBILITY_SNAPSHOT` (`DEPT#{d}#ELIGIBILITY`/`MEMBER#{id}`; per-field-group clocks activeUpdatedAt etc.; PUSH entry per installation), `PRE_PLAN_COPY` (`DEPT#{d}#PREPLAN`/`OCCUPANCY#{id}`), `HYDRANT_COPY`, `ALERT_RULES_COPY` (`DEPT#{d}#ALERT_RULES`/METADATA; as built carries only toneLadder tone2/tone3/escalationThresholdSeconds + defaultRule; clamps numerics), `CAD_INGRESS_COPY`; `SELF_TEST_RUN` (`DEPT#{d}#MEMBER#{m}`/`SELFTEST#{runAt}`, ttl 365d); `CANARY_RUN` (`DEPT#{d}#CANARY#{YYYY-MM-DD}`/`RUN#{ranAt}`, ttl 90d). Access patterns 1–9, 11, 37 in doc.

## Events Produced
`alerting.dispatch.received`, `alerting.dispatch.normalized` (one publish per member/channel/tone; attrs channel, channelTier, toneSequence), `alerting.escalation.triggered` (channel=voice, reason `no_ack_at_tier`), `alerting.delivery.receipt`, `alerting.tone.escalated`, `alerting.mutual_aid.triggered`, `alerting.response.confirmed`, `alerting.canary.result` (direct CloudWatch PutMetricData, not via queue). Last four-plus bridged one-way to platform bus (allow-list: received, response.confirmed, tone.escalated, mutual_aid.triggered). Payload shapes in contracts.json.

## Events Consumed
`personnel.member.updated`, `personnel.eligibility.changed`, `personnel.availability.changed` -> eligibility snapshot; `inspections.preplan.updated`, `inspections.hydrant.updated` -> copies; `platform.config.alert_rules.updated` -> `alert-rules-copy-queue`; CAD ingress copy consumer.

## Dependencies
internal: platform-service (config/CAD source/identity), personnel-service, inspections-service (events only), apparatus-service (riding board). external: APNs/FCM direct, SMS vendor + distinct voice vendor (unselected), SES, EventBridge Scheduler, SNS FIFO, SQS, CloudWatch, KMS.

## Gotchas & Constraints
- Regression tests required: one dispatch/one member -> two distinct provider sends at T+0; member NOT_RESPONDING at tone 1 still gets new tone-2 record.
- Conditional put happens in the channel worker immediately before provider send (not only at fan-out).
- Tone Evaluator: `toneSequence` from payload literal; `TransactWriteItems` with `TONE#` guard + ConditionCheck `toneLadderStatus <> HALTED_MANUAL`; absent `ALERT_RULES_COPY` -> `SKIPPED_NO_CONFIG` + alarm. Advance uses conditional update `currentToneSequence = :expected` (`expectedCurrentToneSequence`). Halt does not cancel pending voice (haltCancelsPendingVoice NOT built); `retoneRespondingMembers`, `voiceEscalatesPerTone`, `callTypeOverrides` designed, not carried.
- Multi-device push: one guard/receipt per member/channel/tone; any device accepted -> SENT, failed device NOT retried; redelivery only if none accepted; MAX_DEVICE_SEND_ATTEMPTS=2; UNAVAILABLE terminal; mutual_aid_prompt branch derives `MAPROMPT#` key, no toneSequence. Webhook receipts update exact receipt SK.
- Scheduler one-time schedules: unique name, `ActionAfterCompletion: DELETE`, schedule DLQ `boxalarm-{env}-alerting-schedule-dlq`, onfailure queue `...-alerting-escalation-onfailure` (paged).
- Response answers: server clamps client `toneSequence` to stored `currentToneSequence`; eta out of range (<-1h/>+24h) stored null, counted `EtaOutOfRange`.
- Snapshot staleness alarm 15 min; propagation <30s p99. Mark-offs: 90-day cap, end-early keeps row.
- Alerting authorizer: reserved concurrency 20; per-route throttle never below 50 rps/burst 100 (call-time roster routes 100/200).
- Notes (mutual-aid) free text: no-PII guidance only. APNs/Android notification identity `{dispatchId}#{toneSequence}` (client-side, see mobile-app).
- No cache on hot path. Canary every 1–2 min enters via ingress.
