# 2026-09-29: Content-Security-Policy for the web SPA — deferred to hosting

Context: security review minor 1 (`.analysis/design-review/security-data.md`) found no CSP on `ui/apps/web`. The web SPA keeps a 3650-day refresh token in `localStorage`. No raw-HTML sink was found, but any XSS would still yield ten years of access.

**Decision: no CSP is added in this change.** There is no web hosting config anywhere in the repo. `infrastructure/` provisions no bucket, distribution or origin for the SPA, and CloudFront is forbidden by N6.1 (enforced by `infrastructure/test/residency-encryption.test.ts`). A CSP belongs in the response headers of whatever serves `index.html`. Putting it there needs that serving layer first.

A `<meta http-equiv>` CSP in `index.html` was considered and rejected as the primary control:
- It cannot carry `frame-ancestors`, which is needed against clickjacking of an admin console.
- It cannot carry `report-to`.
- A wrong origin list silently breaks sign-in, because the Cognito hosted UI and the silent-renew iframe both need their origins listed. It is safer to ship the policy with the hosting change, where it can be tested against the real origins.

**Policy to ship with the hosting story.** Send it as an HTTP response header on `index.html` and `silent-renew.html`. Start in `Content-Security-Policy-Report-Only` for one release, then enforce:

```
default-src 'self';
script-src 'self';
style-src 'self';
img-src 'self' blob: data: https://<platform-assets-bucket>.s3.us-east-1.amazonaws.com;
connect-src 'self' https://<COGNITO_HOSTED_UI_ORIGIN> https://cognito-idp.us-east-1.amazonaws.com
            https://<platform-assets-bucket>.s3.us-east-1.amazonaws.com;
frame-src https://<COGNITO_HOSTED_UI_ORIGIN>;
form-action 'self' https://<COGNITO_HOSTED_UI_ORIGIN>;
frame-ancestors 'none';
object-src 'none';
base-uri 'self'
```

Notes:
- **`connect-src 'self'`** covers `/api/v1/`, because the SPA calls the API same-origin (`apiClient.ts` `API_BASE = '/api/v1/'`). If the API ends up on a different origin, add it.
- **S3 origins.** Presigned uploads (PUT) and downloads/previews (GET) go straight to the platform-assets bucket's regional endpoint, so that origin must appear in both `connect-src` and `img-src`.
- **Styles.** `style-src 'self'` assumes the production build emits CSS files. If any component library injects `<style>` at runtime, the Report-Only phase will show it; add a hash, not `'unsafe-inline'`.
- **Other headers to send alongside:** `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer` (sign-in URLs carry codes), and `Strict-Transport-Security`.
- **What this does not fix:** the refresh token still sits in `localStorage` (minor 1). A CSP narrows what XSS can load or exfiltrate to. It does not make the stored token unreadable to script already running on the origin.
